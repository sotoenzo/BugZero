Ciclo de Vida del Desarrollo de Software (SDLC)

ETAPA 1

Requisitos

Se identifican y documentan las necesidades, objetivos y restricciones del producto. Una buena definición de requisitos alinea al equipo y reduce cambios costosos durante el desarrollo.

Metodologías Tradicionales

Los modelos tradicionales se caracterizan por una planificación secuencial y jerárquica, donde cada fase del desarrollo debe completarse antes de pasar a la siguiente. Este enfoque prioriza la estabilidad y la documentación para minimizar riesgos en proyectos bien definidos.

Elegí un modelo:

Modelo de cascada

Es un modelo secuencial: el proyecto avanza por etapas ordenadas y cada una se completa antes de comenzar la siguiente. Es adecuado cuando los requisitos están claros y cambian poco.

Etapas principales

  1. Requisitos: se identifican y documentan las necesidades del cliente.
  2. Análisis y diseño: se define cómo se organizará y construirá la solución.
  3. Implementación: se desarrolla el sistema de acuerdo con el diseño.
  4. Pruebas: se comprueba que el producto cumpla los requisitos acordados.
  5. Despliegue y mantenimiento: se entrega el sistema y se corrigen problemas posteriores.

¿Cuándo conviene?

Cuando el alcance está bien definido, hay pocas posibilidades de cambio y se necesita planificar el presupuesto, los plazos y la documentación con anticipación.

Ejemplo

Un sistema interno para generar informes regulatorios con formatos y reglas ya establecidos. Primero se acuerdan todos los requisitos y luego se desarrolla y valida la solución completa.

Ventajas
  • Fases y entregables fáciles de planificar
  • Seguimiento claro del avance
  • Documentación ordenada
Desventajas
  • Los cambios tardíos son costosos
  • El producto se valida al final

Modelo en V

Organiza el desarrollo en fases descendentes y relaciona cada fase con una prueba de verificación o validación. Así, las pruebas se planifican desde el comienzo del proyecto.

Desarrollo y pruebas relacionadas

  1. Requisitos del usuario se comprueban mediante pruebas de aceptación.
  2. Diseño del sistema se comprueba mediante pruebas de sistema.
  3. Diseño de arquitectura se comprueba mediante pruebas de integración.
  4. Diseño detallado y código se comprueban mediante pruebas unitarias.

En la parte descendente se especifica y diseña la solución; en la parte ascendente se ejecutan pruebas cada vez más amplias.

Verificación y validación

Verificar es comprobar que cada componente se construyó de acuerdo con su especificación. Validar es confirmar que el producto final resuelve las necesidades reales del usuario.

¿Cuándo conviene?

En proyectos con requisitos estables y alta necesidad de trazabilidad y pruebas, por ejemplo sistemas financieros, médicos o industriales.

Ventajas
  • Pruebas asociadas a cada etapa
  • Permite detectar defectos antes
  • Buena trazabilidad de requisitos
Desventajas
  • Poco flexible ante cambios
  • Requiere requisitos y planificación detallados

Iterativo e incremental

El producto se construye mediante ciclos repetidos (iteraciones) y entregas que agregan capacidades (incrementos). Cada ciclo permite revisar lo aprendido y ajustar el siguiente.

¿Cómo funciona?

  1. Planificar: elegir objetivos y funcionalidades para el próximo ciclo.
  2. Construir: diseñar, desarrollar e integrar la parte seleccionada.
  3. Probar: revisar la calidad y el funcionamiento del incremento.
  4. Evaluar: recibir comentarios y decidir qué mejorar o agregar.
  5. Repetir: comenzar otro ciclo hasta alcanzar los objetivos del producto.

Iteración e incremento

Una iteración es un ciclo de trabajo que revisa y mejora el producto. Un incremento es una parte funcional nueva que se suma a lo ya construido. Pueden usarse juntos, aunque describen ideas distintas.

Ejemplo

En una tienda en línea, el primer incremento permite consultar productos; el siguiente agrega el carrito y luego se incorporan el pago y el seguimiento del pedido. Los comentarios entre entregas orientan las mejoras.

Ventajas
  • Se obtiene valor en entregas parciales
  • Facilita incorporar comentarios
  • Los riesgos se revisan en cada ciclo
Desventajas
  • Exige coordinación entre iteraciones
  • El alcance final puede evolucionar

Metodologías Ágiles

Las metodologías ágiles se caracterizan por una planificación iterativa e incremental, donde el desarrollo se adapta de forma flexible y continua a lo largo de todo el ciclo de vida del proyecto. Este enfoque prioriza la entrega rápida de valor, la colaboración constante y la capacidad de respuesta ante el cambio para minimizar riesgos en entornos dinámicos e inciertos.

Metodología a explorar:

Scrum es un marco de trabajo ágil e incremental diseñado para gestionar y desarrollar proyectos complejos. Se basa en entregas rápidas e iterativas llamadas Sprints (de 1 a 4 semanas), donde el equipo colabora activamente para adaptar el producto a las necesidades cambiantes del cliente de forma continua.

Principios de Scrum

Empirismo

Las decisiones se apoyan en lo observado y aprendido durante el trabajo, no solo en predicciones iniciales.

Transparencia

El trabajo, los avances y los obstáculos deben ser visibles para quienes realizan y reciben el producto.

Inspección

El equipo revisa con frecuencia el progreso, el producto y la forma de trabajar para detectar desvíos.

Adaptación

Cuando una revisión muestra un problema o una oportunidad, se ajusta el plan o el trabajo cuanto antes.

Valores Scrum

Compromiso, foco, apertura, respeto y coraje orientan las decisiones y la colaboración del equipo.

Autoorganización

Developers deciden cómo organizar el trabajo necesario para alcanzar el objetivo del Sprint.
